# Season 4 end-of-season review

Adds an authenticated Alliance Hub section using the existing `hub-content-list/save` routes with `kind: season-review`. Apply `backend/season-review.sql` to the active hub project before publishing the frontend. No Edge Function update, new secret or new authentication system is needed. The migration is repeatable and preserves other hub handlers.

The owner selects exactly 12 active NvSP leaders, including the R5 and the additionally requested reviewer, and snapshots the imported Season 4 member roster. Assignments and members stay fixed for this season. The owner and assigned, currently active NvSP leaders may read reviews; only assigned leaders can vote. Owner-only account management retains its existing restrictions. Revoked leaders cannot read or save even with an old session. Read projections exclude account emails, usernames and password material.

Each member/reviewer/season has one record, including optional comment-only records. Blank votes remain missing; totals count Keep and Cut only. Saves take the reviewer identity from the authenticated actor, ignore nominated reviewer IDs, use optimistic versions, and allow exact retries after uncertain responses. A season-wide transaction lock serializes initialization, closing and saves. Closing blocks votes, while the owner may still record final decisions. Final decisions never modify alliance membership or application status. Private audit history retains changes.

Existing Administration → Logins & passwords assigns and resets individual usernames/passwords. Existing Google-linked leadership accounts continue working. New password-only leadership identities can use an internal, non-deliverable identifier in the legacy email key, linked to the exact existing player profile. This is not a contact address and does not send invitations. Provision only specifically authorized reviewer records; never reset existing credentials during installation. The owner enters new passwords in the existing secure account form.

The page has member/UID search, named-reviewer filters, blank/Keep/Cut filters, aggregate Cut/split/missing filters, and sorting by name or totals. Details show all 12 responses and comments. Summary and detailed vote-log CSV downloads use the currently filtered member set; the detailed log includes all 12 reviewers for those members. CSV formula-like user content is neutralized. These are exports, not a live Google Sheets sync. When importing into Sheets, turn off text-to-number/date/formula conversion to preserve long UIDs.

`season-review-guide.html` uses the actual review component with fictional, in-memory records. It provides a six-step walkthrough with highlighted controls and an expandable owner account guide. It does not authenticate, save to the backend or persist entered training data. A link to the guide appears beside the Season 4 heading.

Validation: `node --test tests/*.test.mjs`. For transactional backend validation before initial setup, wrap the migration and `backend/verify-season-review.sql` in one transaction and roll back. The verification checks assignment counts, access, forged reviewer IDs, repeat initialization, idempotent retry, stale edits, blank votes, roster boundaries, private projections, owner-only final decisions, closing/reopening, revocation and table/function grants. Run against a disposable database or before Season 4 initialization; it intentionally refuses to overwrite an initialized season.

Rollback the frontend to the preceding revision if needed. Preserve review tables and audit records; do not delete saved reviews or reset leaders' passwords as part of a rollback.

## Owner notes

The Notes from RaidARQN column stores a separate shared note per Season 4 member. Only the active master with account-management permission may edit it; all assigned reviewers may read it. Notes have independent optimistic versions, exact-retry handling, a 4000-character bound and private audit entries. They remain editable after voting closes, do not count as votes and appear in both CSV exports and member Details. Reapply season-review.sql before publishing this frontend; it preserves existing review data and credentials.
